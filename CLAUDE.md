# CLAUDE.md

Backoffice for a restaurant's staff (PoC, 2026-10-10): Nuxt 4 SPA (bun, shadcn-vue) with a Nitro backend-for-frontend on the Shopware Admin API. Every restaurant installation (own Shopware, one storefront per branch, order-printer, like Pizzeria La Fattoria) runs its own backoffice, configured by env (`.env.example`). Replaces the Shopware Administration for restaurant staff; Shopware stays the commerce core. Read `docs/adr/0001-eigenes-backoffice-statt-shopware-admin.md` and `docs/plan.md` first. Part of the ShopBite monorepo, see `../CLAUDE.md`.

## Commands

```bash
bun install
bun run dev       # http://localhost:3010, needs the quickstart stack, see README
bun run lint      # ESLint (@nuxt/eslint) + Prettier; lint:fix formats
bun run typecheck # must stay at zero errors
bun run test      # Vitest: server logic against real La Fattoria data (test/fixtures)
bun run build
bun run roundtrip # every dish loaded + saved unchanged must leave Shopware identical (needs a running stack)
bunx shadcn-vue@latest add <component>   # see "shadcn" below
```

## Rules

- The browser only calls `/api/*` of this app. Shopware tokens live in the sealed session cookie (`server/utils/session.ts`); never return a token or the Shopware URL to the client.
- Every Shopware call goes through `adminApi()` / `adminSearch()` with the logged-in user's token, so Shopware's ACL decides. Never add an integration key with more rights. No central service, no tenant registry: one deployment talks to one Shopware.
- The API speaks restaurant terms (`shared/types/backoffice.ts`); translation to Shopware entities happens only in `server/`. Validate every request body with Zod.
- Multi-entity writes (dish, section) are ONE `/_action/sync` request. Upserts only add mapping rows; delete removed ones explicitly (`product_property`, `product_category`, `product_tag`, …). Write only fields the backoffice knows; merge custom fields; keep other currencies and categories outside the menu.
- Tests: `test/*.test.ts` stub the Nitro auto-imports (`adminSearch`, `adminApi`, `currentSalesChannel`, the label catalogue) with `vi.stubGlobal` and answer from `test/fixtures/lafattoria.json` (refresh it from a local import when the data model changes). Logic that needs no request goes into pure functions (`profileFromMe`). CI (`.github/workflows/ci.yml`) runs lint, typecheck, test, build.
- Saving an untouched dish must not change Shopware at all: write texts, prices, custom fields and dimensions only when they differ (unset equals default/empty). Variants come from configurator settings AND the children's options, so a missing setting never deletes a variant. Check with the round trip over the real La Fattoria menu (README, "Mit echten Daten testen").
- Never edit product SEO URLs: the storefront opens dishes via `?produkt=` (storefront#289). Category SEO URLs are fine (old path stays as non-canonical alias, storefront redirects 301).
- Branches are sales channels. Menu, hours and settings are per selected channel (`currentSalesChannel`), orders span the person's channels (`restaurantChannels`).
- Roles: capabilities come from the Shopware privileges in `/_info/me` (`server/utils/profile.ts`, Management = `product:update`). Every API area is mapped to a capability in `server/middleware/auth.ts`, every page sets `definePageMeta({ capability })`. Branch binding is the user custom field `shopbite_sales_channel_ids`; Shopware does not know it, so anything touching an order or a channel must check against `restaurantChannels()`.
- Allergens and additives are a fixed catalogue (`shared/utils/labels.ts`), stored as property groups "Allergene"/"Zusatzstoffe" with `shopbite_code`. Never let them become free text; keep unknown options of these groups when saving.
- Passkeys (fingerprint / Face ID): WebAuthn runs in the ShopBite plugin (shopware-plugin `src/Passkey`, grant `shopbite_passkey` on `/api/oauth/token`, routes `/api/_action/shopbite/passkey/*`); the backoffice only proxies (`server/api/auth/passkey/*`, `server/api/passkeys/*`) and uses `@simplewebauthn/browser` in `login.vue`, `zugang.vue` and `PasskeyHint`. The relying party is the backoffice host, set in the plugin configuration (`passkeyRpId`, `passkeyOrigins`). Both logins end in `assertCanWork()`.
- PWA (`@vite-pwa/nuxt`): the service worker precaches the app shell only (`/` is prerendered), never `/api` responses, orders must be live. The manifest is the server route `server/routes/manifest.webmanifest.ts` (restaurant name from the env), icons in `public/icons`. Without network the auth middleware sends to `/offline` (back automatically when online), `OfflineNotice` shows while a page is open, `app/error.vue` replaces Nuxt's English error page. Test PWA behaviour on a production build (`bun run build && PORT=3011 bun .output/server/index.mjs`), dev has no service worker.
- "Jetzt drucken" only sets the order custom field `shopbite_print_requested_at` (`server/api/orders/[id]/print.post.ts`, branch check like status changes); the order printer prints and sets `shopbite_printed_at`. "Heute" shows "Druck angefordert", "Gedruckt um", or "Drucker antwortet nicht" after 60 s.
- Sections have two levels (section › sub-section, like the storefront): `loadSections()` returns the tree, `rows` the flat list of both levels; moves rewrite the `afterCategoryId` linked list of the old and new siblings (`siblingsOf`). A section with sub-sections cannot become a sub-section; deeper categories are left alone and fold into their sub-section in the menu list.
- Extras come two ways: a fixed list per dish ("productList" cross-selling, `extras`) or an extras group used at many dishes (`server/utils/extraGroups.ts`, page `/speisekarte/extras`): a Shopware product stream linked by a "productStream" cross-selling (`extraGroupIds`). The backoffice edits only streams whose single condition is "Produkt ist eins von" (`productListFilter`, equalsAny on `id`, as the Shopware Administration writes it) and writes just that filter's `value`; other streams are read-only, streams of dynamic categories are no extras groups. A group in use cannot be deleted.
- After every menu write (dish, product toggle/price, section, extras group) call `purgeStorefronts(event, { products | categories })` (`server/utils/storefrontCache.ts`, storefront `POST /api/_cache/purge`, env `NUXT_STOREFRONT_URLS` + `NUXT_CACHE_PURGE_SECRET`). It never throws: an unreachable storefront only sets `x-storefront-stale`, `useBackofficeApi` turns that into `useStorefrontStale()` and the layout shows a warning.
- Ordering on/off and delivery time go through the plugin route `/_action/shopbite/settings/{salesChannelId}` (privilege `shopbite_settings:update` = capability `settings`); never write `/_action/system-config`, no role has `system_config:*`.
- Never move an order out of `open`: the order-printer does that after printing (`../order-printer`).
- New Shopware privileges the app needs go into `docs/notes/management-privileges.json` or `personal-privileges.json`, then `python3 -I scripts/create-poc-users.py`, later the plugin's role installer.
- UI follows the ShopBite CI (`docs/ci.md`): tokens in `app/assets/css/main.css` (primary `#cc4800`, never the raw brand orange for text), Public Sans self-hosted, logo in `public/brand/`, warnings use the yellow `warning` tokens. shadcn-vue style **mira** from `app/components/ui` (owned code, auto-imported without prefix): dense with a mouse, and every interactive component carries `pointer-coarse:` sizes for touch (44 px, 16 px input text); pages use `min-h-8 pointer-coarse:min-h-11` for tappable rows. Dark mode via the `.dark` class (`useColorMode`, `ColorModeButton`, inline script in `nuxt.config.ts`), every colour must come from a token; app components `FormSection`, `ListField`, `ErrorAlert`. Visible focus, `role="alert"` / `role="status"` instead of toasts, German copy without dashes as sentence connectors.
- shadcn: reka-ui sets `data-state="checked"`, the nova styles use `data-checked:`; `main.css` maps the variants. On this machine the CLI breaks on Debian's `/usr/share/nodejs/eslint-scope` ("Invalid Version: main"): run `bun add -d eslint-scope@9.1.2` before `shadcn-vue add` and `bun remove eslint-scope` after. After adding or re-adding a component, add the `pointer-coarse:` sizes again and fix the NativeSelect emit type (`[value: AcceptableValue]`). Check that `main.css` has no Google Fonts import afterwards (the CLI adds one).
